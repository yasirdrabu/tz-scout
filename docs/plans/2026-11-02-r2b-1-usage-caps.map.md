## GAPS / DECISIONS FOR THE PLAN
1. Cap storage: new `integrations` tables (e.g. `usage_cap` {scope connection|api_key, unit, period day|month, limit, overage_until}, counter/reservation rows, `notice_sent` once-per-period marker) vs summing `call_log`. Atomic `checkCap` (ENR-E3-S2-AC4) needs a lock/counter row; reserve-then-settle in gateway.
2. Gateway API: `CallOpts` additions (reserve units, cap keys); refusal slug `blocked_by_cap` for AI fallback + HTTP 429 `cap-reached` w/ `resets_at` for API callers; write `blocked_by_cap` call_log row; `checkCap` returns ok|warn|blocked + resetsAt.
3. Period boundaries in tenant timezone (`tenantTimezone`); replace UTC `date_trunc` in `overview.ts:44`.
4. Default caps seeding (Apollo 2000 credits/mo, Vibe 1000/mo, Claude 20000 cents/mo, HubSpot 50000 calls/day): needs integrations tenant.created consumer (none) + backfill for existing tenants/seed CLI.
5. Key caps: `api_key.daily_arrival_cap` vs enforced `source.dailyArrivalCap`; route arrival cap through INT or leave; `monthly_enrichment_credit_cap` default 0 is unread (enforce at request/approve).
6. Notices to owners: no notification system. Minimal option: events only + banner/summary on Integrations + audit; "raise cap / allow one more period" endpoints need audit (`audit(ctx,...)` helper used in connections.ts).
7. Events: define `integrations.usage.recorded` (emit per costed call; fields: provider, connectionId, units, unit, costCents, module, plus ENR context requestId/searchRunId/accountId/requestingSourceId/principal - call_log has no source/account columns) and `threshold_reached` (level warn|block). Currency: only cents stored; tenant currency conversion not modelled.
8. Price per credit ("money per credit lives on the INT connection") -> connection.settings or new column; `provider_price` table in ENR; seed Apollo defaults with "Check these against your Apollo plan".
9. Adapter interface for Apollo/Vibe owned by ENR (`estimate`, `run`, `health`; base `Adapter` only has `test()`); live adapters: write against stubbed responses, or mock-only (api-gaps "Apollo, Vibe live LATER R1d" => `live-unavailable`). Mocks deterministic by input, return arrival.v1 items + creditsUsed. v1 fixtures/mappers (apollo.ts, vibe.ts, vibeExport.ts) are outside src (check `reference/`). `company_data` out of scope.
10. Scope of ENR in R2b: requests/approval + results/failures (E1, E3, E4) vs saved searches/search_run/Searches page (E2; no screen spec; `searches:manage` exists). Kinds: website_read needs new `read_website` task + fetcher; signals_refresh; email_reveal.
11. Job waits on cap: no platform support. Pick: request stays `approved` ("Waiting for budget: Apollo monthly limit reached"), handler catches cap error and returns without throwing, resume via scheduler/sweep job or on cap raise/reset event. State machine flagged->approved|declined->running->completed|failed|cancelled(+14-day expiry job, duplicate join with watchers table).
12. Result submission: ctx.access.sourceId = provider vendor source (qualified-leads pattern); external_ref = request id; vendor source `dailyArrivalCap` (500) may reject; requester only in `notes`; partial results submitted before marking failed/partial; decline -> `recordFeedback('enrichment_declined')`.
13.
