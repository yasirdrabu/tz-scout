## 3. Where "pause paid calls" hooks in

- One place catches every paid call: `runCall` before `reserve` (gateway.ts:226-255). A workspace budget check there that throws
  the same `blocked_by_cap` (or a new slug the same handlers know) gets for free: the `call_log` refusal row, the AI runner's rules
  fallback / rethrow (runner.ts:358-370), ENR's waiting state (run.ts:408-418), and the worker's put-back (worker.ts:542).
  But: ENR's own pre-check uses `checkCap` (run.ts:390), so it needs a budget-aware check too, and its words "Waiting for budget:
  {Provider} monthly limit reached" and `capBlocked`'s "raise it in Settings, Integrations" would be wrong for a budget pause.
- "Paid" = providers whose calls carry money: `anthropic` (cost_cents) and `apollo`/`vibe` (credits x price). `website` costs only
  through its Claude run; `hubspot` is never paid. A rule "unit credits or cost_cents" picks these from `DEFAULT_CAPS`.
- Spend to compare: needs money per call **before** the call (AI: `reserveCents`; ENR: `units` x price) and settled money after.
  Today only AI has money in `call_log`; R3a must price credit calls at record time (gateway or ENR passes `costCents`).
- Mock calls: AI mock settles 0 cents, ENR mock counts credits; decide whether sample data counts toward the budget (locally
  nothing would ever pause AI).
- UI today when a cap is reached: Integrations banner lines via `capLines` (web-ui/src/features/settings/integrations/words.ts:19-31,
  IntegrationsTab.tsx:31), Manage panel meter and `Allow until {date}` (UsageLimit.tsx:18-80); enrichment requests show
  `waiting_reason`; API 429 `/cap-reached`. No global banner, no email, no event consumer of `usage.threshold_reached`.
