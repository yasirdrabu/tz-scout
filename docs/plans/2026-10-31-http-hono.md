# HTTP layer on Hono Implementation Plan

> **For agentic workers:** Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove Next.js from the backend (decision W4). One Node HTTP server built on Hono serves
the API at `/api/v1` (C1), sign-in at `/api/auth`, the inbound webhooks, the health checks and the
built web-ui app at `/` with an `index.html` fallback (W2), all on one origin.

**Architecture:** The 98 route handlers in `src/app/**/route.ts` already take a web `Request` and
return a `Response` (through `v1Route` and friends) and import nothing from Next, so they move
unchanged in behaviour to `src/http/routes/**` and are mounted by a route table. `scout web` starts
the Hono server with `@hono/node-server`. tsup bundles it with the CLI. Next, its config, its build
and its dependencies go.

**Tech Stack:** hono, @hono/node-server (exact versions at least two weeks old), the existing
modules, tsup, Vitest, Playwright.

**Spec:** `docs/spec/web-ui/index.md` W2, W4, C1, "Backend changes this needs" 1 and 2;
`docs/spec/architecture/stack-and-layout.md`, `api-and-mcp-conventions.md`,
`deployment-and-iac.md` (update them).

## Global Constraints

- Handler behaviour does not change: same permissions, problem+json, snake_case, idempotency,
  CSRF, correlation ids. The only visible change is the prefix: `/v1/...` becomes `/api/v1/...`,
  with no alias for the old path (C1: nothing outside Scout calls it yet).
- Everything that names the old prefix moves with it: web-ui (`API_BASE`, MSW handlers, tests),
  the Vite dev proxy, e2e, CI smoke test, the MCP server if it builds URLs, the developer docs and
  `docs/spec/public-api`, the HubSpot inbound webhook path (`/api/v1/inbound/hubspot/{connectionId}`),
  sample requests in screens.md, README, CHANGELOG.
- `/healthz` and `/readyz` stay at the root. `/api/auth/*` and `/api/dev/sign-in` keep their paths.
- Static app: `/assets/*` and other files from `web-ui/dist` with long cache for hashed assets;
  any other GET or HEAD that is not under `/api/`, `/healthz`, `/readyz` returns `index.html`
  (no-cache); other methods on app paths 405; unknown `/api/*` paths the API's problem+json 404.
  The interim Next fallback `src/app/[[...app]]/route.ts` is replaced by this.
- Request limits stay as today (body size limits in `v1/_lib/intake.ts` are enforced by the
  handlers; also set a server-level max body size at least as large).
- Graceful shutdown: SIGTERM, SIGINT and the IPC "shutdown" message stop accepting, finish in-flight
  requests (10 s cap), close db pools and NATS, exit 0.
- Never touch the user's `.env` or dev `scout` database. Commit after each task with conventional
  messages ending in the Co-Authored-By line; `git add` specific paths.

## Review Focus

1. Every route.ts is mounted at the right path and method; a test fails if one is missed.
2. Colon actions (`/api/v1/members/mbr_x:suspend`) and catch-alls (`[resource]`, `[...all]`) route
   exactly as before.
3. Auth cookies, the sign-in redirect and the return path work on the new server (better-auth
   `baseURL`/`basePath`, `APP_PUBLIC_URL`).
4. The client IP for audit and keys still comes from `clientIp` with `SCOUT_TRUSTED_PROXY_HOPS`.
5. Production image: `scout web` serves app, API and health on 4240; the CI smoke test proves it.
