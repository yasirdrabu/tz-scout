## 3. What is missing

1. Journey read model in analytics: `account_journey` (+ `source_touch`, `decline`) with consumers of `intake.arrival.resolved`
   (arrived_at, attribution, batch), `routing.stage.changed` (first-entry per stage, skipped stages filled), `routing.assignment.*`,
   `routing.status.changed`, `crm.deal.changed` (won amount), `scoring.account.scored` (practice/offer), `accounts.account.merged`.
2. A backfill for accounts that predate the consumers (replay the 90-day stream, or seed from routing `stage_change` + intake
   arrivals + crm deals once through a CLI), and "Updated <time>".
3. Pure domain: `funnelCounts`, `conversion`, `allocate`, `sourceMetrics`, insight text; unit tests with hand-built journeys.
4. APIs: `GET /api/v1/analytics/funnel` (totals, per-row cost and status, filters, target), `GET /api/v1/analytics/sources/{id}/
   performance` (baseline, rank, prev/next, insight, batches, won accounts), `GET /api/v1/costs/by-source` (or `?group_by=source`)
   + three tile numbers in `/costs/summary`. Data limits and seller scope; spend hidden without `costs:read`.
5. Ledger targets: source (and maybe batch) on manual lines; lines with no account become "Shared costs".
6. Target cost per won setting; minimum-sample rule.
7. Trust (intake): `arrival_outcome` consumers, `source_trust_history`, nightly job + schedule seed + backfill, conflict-loss drop,
   publish `trust_changed`, trust in `/sources` and `/score`; UI trust number/bar/filter/legend, tile, card, trend, account note.
8. Web UI: Funnel §16, Drill §17, Costs R3b tiles + "Cost by source", Sources `See in funnel` + Cost per win tile.

## 4. Conflicts

- **Fixed stage columns vs configurable stages.** index.md:19 has `reviewed_at`, `engaged_at`...; stages are per-workspace keys,
  with a `back_to_nurture` exit the spec lacks and renamable labels ("Sent" for arrived). Store first-entry per key (jsonb
  `stage_at` or a `journey_stage(account_id, stage_key, entered_at)` table) and order by `routing.stages.changed` / `GET /stages`.
  Deleted stages: keep history, drop from the columns.
- **Arrived has no stage event.** account-funnel-by-source.md:13-14 says stage times come only from `routing.stage.changed`, but the
  first stage is never published; arrived_at must come from `intake.arrival.resolved` (index.md:56 already implies it).
- **Two sets of source numbers.** Sources page (any source, children rolled up, current stage) vs funnel (first source, furthest
  stage reached). Sent/Won will differ between §10/11 and §16/17 for the same source. Either move Sources stats onto the journey or
  label the difference.
- **Attribution level.** index.md:19 "first arrival's person-level source, or the most specific level present" contradicts itself;
  the mockup's rows mix agents, lists, partners, CRM and vendors (the arrival's `closest_source_id`).
- **Return value.** Mockup 1929/3087 "Won value uses each offer's price" (average offer price); screens.md:702-703 and Decision 26
  (api-gaps.md:107) say actual won amounts. Deals with no amount are undefined.
- **Minimum sample.** `conversion` min 5 (account-funnel-by-source.md:39); screens §16-17 and mockup use 10 sent for cost per won,
  rank and insight; `min_sample` exists only on `scorecard_target` (api-gaps.md:1090).
- **Target cost per won.** screens §16/17/18 show "Target {target}"; no setting in any spec (api-gaps.md:1089).
- **Seller sees spend?** Funnel is `analytics:read` (sellers, viewers) yet shows Spend and Cost per won; access-and-exports.md:7-9,15
  hides costs from sellers except own cost per won.
- **Re-targeting by correlationId is mostly moot.** R3a already stamps `accountId` on the usage event; `ai.run.completed` has no
  account to offer. Left: intake AI calls (arrival normalise -> arrival's account/source; CSV mapping -> import's batch/source),
  and enrichment for an agent's request (`requestingSourceId`: account or requesting source?). Spec cost-ledger.md:20 says account.
- **Manual line targets.** Partner fees per source (mockup Kestrel $9,000) need a source target; R3a manual lines have none.
  cost-ledger.md:24-27 also wants hours x role rate, batch, practice, offer targets.
- **Scope creep in spec.** Activity view, any-source mode, level switch, grouping by practice/offer/batch/seller, time in stage,
  stalled-accounts list, drill-to-accounts on every count, CSV + audit, agent MCP tool, rebuild with republish: none on §16-18.
- **Trust owner.** Roadmap lists trust under analytics; spec puts it in intake (SRC-E1) reading its own events, independent of ANL.

## 5. Proposed split (two plans)

- **R3b-1 Funnel and cost per win** (analytics + web-ui, ~6-7 tasks): (1) journey/touch/decline schema + consumers + backfill CLI;
  (2) domain `funnelCounts`/`conversion`/`allocate`/`sourceMetrics`/insight + unit tests; (3) manual-line source target + intake AI
  line targets + target-cost setting; (4) funnel API + source performance API + costs by-source and summary tiles, scopes; (5) UI §16
  Funnel; (6) UI §17 Drill + Sources `See in funnel` / Cost per win tile; (7) UI §18 R3b tiles + "Cost by source", spec updates.
- **R3b-2 Source trust** (intake + scoring + web-ui, ~4-5 tasks): `arrival_outcome` consumers and backfill; pure trust formula +
  unit cases; nightly job + history + `trust_changed` + conflict-loss drop; trust in `/sources`, `/score`, account breakdown; UI
  trust column/bar/filter/legend, tile, Overview card, trend, notes.
  Independent of R3b-1 (own events), so either order; R3b-1 first because the Costs/Funnel gap is user-visible today.
