# R3a Cost ledger, budgets and the Costs screen Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every paid call is priced from rates the owner sets. Costs land in a ledger next to manual cost lines. Each category has a monthly budget that alerts at 90%, and AI usage and Data vendors pause at 110% until the budget is raised. The Costs screen shows where the money goes.

**Architecture:**
- **Integrations** owns provider rates. It prices live paid calls and publishes `integrations.usage.recorded`.
- **Analytics** is a new module. It owns the ledger (`cost_line`), budgets and budget levels, and publishes `analytics.budget.level_changed`.
- **The pause:** integrations consumes `analytics.budget.level_changed` into its own pause flag. The gateway then refuses paid calls in a paused category with a cap-like error, so the existing waits and fallbacks apply.
- **Boundaries:** integrations never imports analytics services, only its contracts.

**Tech Stack:** TypeScript, Hono, Drizzle + Postgres (RLS, one database per workspace), outbox + NATS, React 19 + TanStack Query, vitest, msw, Playwright.

**Spec:** `docs/spec/analytics/cost-ledger.md`, `docs/spec/analytics/index.md`, `docs/spec/analytics/access-and-exports.md`, `docs/spec/integrations/usage-caps.md`, `docs/spec/web-ui/screens.md` §18, `docs/spec/web-ui/api-gaps.md` (Decision 26, rows 1089-1101). Code map: `docs/plans/2026-11-05-r3a-costs.map.md`.

## Product decisions (user, 2026-11-02 and 2026-11-05)

1. **Rates set in Settings.** Money = what the provider reports (tokens, credits) × a rate the owner sets per provider. Defaults are pre-filled from list prices. Sample and mock data cost $0.
2. **Per-category monthly budgets** for the mockup's five categories: Partner fees, Data vendors, Agents and hosting, Lists and events, AI usage. Only AI usage and Data vendors pause, at 110%. Every category alerts at 90%.
3. **Manual cost lines** are in R3a: add, edit and void, each with amount, date, category and note.
4. **Access.** Owners and leaders set budgets. Owners, leaders and operators see Costs. Sellers and viewers do not.
5. **At 110%,** paid calls wait like a usage limit:
   - AI briefs fall back to rules, and enrichment requests wait.
   - Everything resumes when the budget is raised.
   - Calls already running finish.
   - The 90% alert and the pause show in the app only.

## Rulings (controller, 2026-11-05)

1. **Rates.**
   - **Table:** `integrations.provider_rate(tenant_id, provider, item, cents_per_unit numeric(14,6), updated_by, updated_at)`, with primary key (tenant, provider, item).
   - **Items:** for `anthropic`, `{model}:input` and `{model}:output` per token. For `apollo` and `vibe`, `credit`.
   - **Defaults:** come from code: the existing AI `PRICES` (converted per token) and the provider's existing `settings.cents_per_credit`, else `DEFAULT_CENTS_PER_CREDIT`. A missing row reads the default.
   - **API:** `GET /api/v1/integrations/{provider}/rates`, `PUT` (`integrations:manage`) `{ rates: [{ item, cents_per_unit }] }`. A rate below 0 is refused with 400 "A rate can't be negative."
2. **Pricing.**
   - Add `priceCents(ctx, provider, usage: { item: string; units: number }[]): Promise<number>` to `@/modules/integrations`. It rounds to whole cents, half up.
   - The AI runner uses it in place of the code `PRICES`. Enrichment uses it in place of `costOf`'s settings read.
   - Only live calls are priced. Mock and sample calls are 0.
   - Credit calls now write `call_log.cost_cents`.
3. **Usage event.**
   - The gateway publishes `integrations.usage.recorded` v1 from the call-log transaction, only for a successful call with `costCents > 0`.
   - Payload: `{ callId, provider, operation, module, units, unit, costCents, accountId: string | null, correlationId, occurredAt }`.
   - `CallOpts` gains `accountId?`, which enrichment and the AI runner pass when they know it.
4. **Categories.**
   - Stored keys: `partner_fees`, `data_vendors`, `agents_hosting`, `lists_events`, `ai_usage`.
   - Labels: "Partner fees", "Data vendors", "Agents and hosting", "Lists and events", "AI usage".
   - Provider map: `anthropic` → `ai_usage`; `apollo` and `vibe` → `data_vendors`.
   - Pausable categories: `ai_usage` and `data_vendors`. Integrations keeps this map in its contracts; analytics imports it from there.
5. **Ledger.**
   - **Table:** `analytics.cost_line(id 'cst_', tenant_id, occurred_on date, category, provider null, amount_cents bigint, origin 'usage' | 'manual', origin_event_id unique null, account_id null, note text null, created_by null, created_at, voided_at null, void_reason null, voided_by null, replaces_id null)`.
   - **Usage lines:** one per `integrations.usage.recorded`, deduped on the event id. `occurred_on` is the tenant-timezone date of `occurredAt`.
   - **Edits:** lines are never updated in place. Editing a manual line voids it with the reason "Edited" and inserts a new line with `replaces_id`.
   - **Voiding:** any line can be voided with a reason. Manual lines are allowed in every category.
6. **Money and month.**
   - Amounts are integer cents in the tenant currency, with no conversion.
   - A month is the calendar month in the tenant timezone.
   - Spend excludes voided lines.
7. **Budgets.**
   - **Table:** `analytics.cost_budget(tenant_id, category, month 'YYYY-MM', amount_cents)`.
   - **Carry-forward:** a month's budget is the row for that month, else the latest earlier month's row.
   - **No budget:** none, or 0, means no alert and no pause.
   - **Saving:** `PUT /api/v1/costs/budgets` `{ month, budgets: [{ category, amount_cents }] }` writes that month's rows (`budgets:write`). The current and future months can be saved; a past month gets 409 "Past months can't be changed."
8. **Levels.**
   - **Scale:** `ok` below 90%, `alert` from 90%, `over` from 100%, `paused` from 110%. A category that can't pause tops out at `over`.
   - **Stored state:** `analytics.budget_state(tenant_id, category, month, level)` holds the last level.
   - **When recomputed:** after every line insert or void, and every budget save, for the current month.
   - **Event:** a change publishes `analytics.budget.level_changed` v1 `{ category, month, level, spentCents, budgetCents }`.
   - **New month:** the first line of a new month starts from `ok`, so a pause ends at the month boundary.
9. **Pause.**
   - **Flag:** integrations consumes `analytics.budget.level_changed` into `integrations.paid_pause(tenant_id, category, month, paused boolean)`.
   - **Gateway:** before `reserve`, a paid provider whose category is paused for the current tenant month throws `budgetPaused(category)`. It uses the cap slug family, so `isCapWait` is true and the worker puts the job back. The detail reads "{Category} is over its monthly budget. An owner or leader can raise it on the Costs page."
   - **Pre-check:** `checkCap` also returns blocked when paused.
   - **Enrichment's wait:** reads "Waiting for budget: {Category} is over its monthly budget".
   - **AI:** briefs fall back to rules as they do for a cap.
   - **Mock calls too:** the pause applies to every call to a paused provider, live or mock, so it can be seen working on sample data.
   - **Timing:** the pause follows the event, so calls already running finish. A few calls may start in the moment before the flag is set; that's accepted.
10. **Permissions.**
    - **New permissions:** `costs:read` (owner, leader, operator), labelled "See costs", and `budgets:write` (owner, leader), labelled "Edit budgets". Both go in the "Pipeline and money" group.
    - **Existing:** `costs:write` (owner, leader, operator, "Record costs") covers manual lines and voids.
    - **Nav:** the Costs item and route require `costs:read`.
    - **API:** every `/costs` read requires `costs:read`.
11. **Costs API (analytics).** Each call names its permission.
    - **Summary:** `GET /api/v1/costs/summary` (`costs:read`) returns:
      - `{ month, spend_month_cents, budget_month_cents, spend_90d_cents }`;
      - `categories[{ key, label, spend_90d_cents, spend_month_cents, budget_cents, level, pausable }]`;
      - `months[{ month, spend_cents, budget_cents }]` for the last 6 months including the current one, where the budget is the sum of the category budgets.
    - **Lines:** `GET /api/v1/costs/lines?category&from&to&include_voided&cursor` (`costs:read`) returns 50 a page, newest first.
    - **Add:** `POST /api/v1/costs/lines` (`costs:write`, people only) takes `{ occurred_on, category, amount_cents, note }`. The amount must be positive: "Enter an amount above zero." The note is up to 500 characters.
    - **Edit:** `PATCH /api/v1/costs/lines/{id}` (`costs:write`) applies to manual lines only. Others get 409 "Only costs added by hand can be edited."
    - **Void:** `POST /api/v1/costs/lines/{id}:void` (`costs:write`) takes `{ reason }`, which is required.
    - **Budgets:** `GET /api/v1/costs/budgets?month` (`costs:read`) and the PUT in Ruling 7.
12. **Costs screen (R3a parts of §18).**
    - **Tiles:** "Spend this month", "Budget used" ("{n}%" of the monthly total), and "Last 90 days".
    - **"Where the money goes":** 90-day spend by category.
    - **"Monthly spend":** 6 bars against the summed budget line. Bars are red over 100% and amber from 90%.
    - **"Monthly budgets":** per category for the current month. Each row shows used, "of {budget}", and "{n}% used", "Over by {x}" or "{x} left".
      - `Edit budgets`, `Cancel` and `Save budgets` only for `budgets:write`.
      - The save toast reads "Budgets saved. Monthly total {x}."
    - **"Cost lines":** a list with `Add cost`, `Edit` and `Void` for `costs:write`, and a "Show voided" toggle.
    - **Banners:** on Costs and on Settings › Integrations, for `costs:read` holders:
      - "{Category} has used {n}% of its {Month} budget." at alert or over;
      - "{Category} is paused: it is over 110% of its {Month} budget. Raise the budget to resume." when paused.
    - **Left for R3b:** Cost per account sent, Cost per won, Return on spend and "Cost by source".
13. **Rates UI.** Each paid provider's Manage panel in Settings › Integrations gets a "Prices" section:
    - Claude: per model, "Input, $ per million tokens" and "Output, $ per million tokens".
    - Apollo and Vibe: "Cents per credit".
    - The save toast reads "Prices saved."
14. **Not in R3a:** the INT-E4-S4 usage page, re-targeting lines to accounts and sources by `correlationId` (R3b allocation), hour rates, CSV export, email alerts, and "Allow over".
